# 開発体制・Git運用・制作計画

[目次へ](./README.md) · [技術](./technology.md) · [未決定事項](./open-decisions.md)
## 1. GitHub運用

```text
feat/* → Pull Request → dev → Pull Request → main
                  ukyoが確認・マージ       ukyoが確認・マージ
```

- `main`: 安定版・本番反映元。
- `dev`: 開発統合ブランチ。
- `feat/*`: 各機能の作業ブランチ。
- featからdevへのPR作成は各実装者。マージは原則ukyo。
- コンフリクトは原則PR作成者が解消。
- 直接push制限のGitHub設定は導入推奨（暫定）。

## 2. 実装順序

1. 基本UIとGoogle Maps表示を試作。
2. DBモデル・API入出力の型を先に定義。
3. `public/data` 等のモックをAPIクライアント経由で利用し、並行開発。
4. D1接続・テストAPI・認証・投稿APIを実装。
5. ピン投稿・閲覧の動作を完成。
6. 旅行計画の編集・公開・参照管理を実装。
7. いいね・検索・通報・画像削除等を統合。
8. デプロイと動作確認

Googleログインをどの時点で組み込むかは未決定。認可を伴うAPIの前に認証の基盤を用意するのが暫定提案。

## 5. テスト

詳細な自動テスト基盤は作らず、基本的に動作確認を優先する方針。ただし最低限、以下を確認する（暫定チェック項目）。

- 未ログインでの公開閲覧と書き込み拒否。
- 他人の下書き閲覧・編集の拒否。
- ピンの下書き→公開、公開→下書き拒否。
- 下書きピン入り計画の公開拒否。
- 公開計画への下書きピン追加拒否。
- 投稿削除後の計画内欠損表示。
- 画像3枚・5MB制限、削除時のR2消去。
- 退会時の関連データ削除。
- 同時アクセス時の主要画面の表示。
