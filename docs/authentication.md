# 認証・ユーザー管理仕様

[目次へ](../README.md) · [API](./api.md) · [セキュリティ](./security-operations.md)

## 1. 確定方針

- Googleログインを優先する。
- 誰でも公開コンテンツを閲覧できる。投稿・計画作成はログイン必須。
- 個人情報の保存を最小化する。
- 一意の公開ユーザーID（handle）と、重複可能な表示名を別に持つ。
- handleは登録後に変更不可。
- アカウント削除時は所有する投稿・計画・画像をすべて削除する。

## 2. Googleログインフロー（暫定）

1. ReactからGoogle Identity ServicesでIDトークンを取得。
2. サーバーへ送信。
3. サーバーで署名・`iss`・`aud`・有効期限等を検証。
4. 検証済み `sub` をユーザーの安定識別子として使用。
5. 初回ならhandle・表示名を登録し、既存なら対応する内部ユーザーIDを取得。
6. アプリのセッションを発行する。

GoogleのIDトークンを検証せずにクライアントのプロフィール情報だけでログインを成立させてはならない。

**方針**: Google CloudのOAuth Client ID・許可オリジンとCloudflareの環境変数・シークレットはboo_manKnowが管理する。フロントのモックログインは本番のトークン検証・認可の代わりにならない。

## 3. 保存する情報（暫定）

| データ | 保存 |
|---|---|
| アプリ内部ID | 必要 |
| Google `sub` | 必要 |
| handle | 必要 |
| 表示名 | 必要 |
| Googleパスワード | 保存しない |
| Googleアクセストークン | 原則保存しない |
| メールアドレス | 原則保存しない |
| セッション秘密値 | 平文でDBに保存しない |

Googleログインを利用しても認証関連データが一切不要になるわけではない。

## 4. セッション（暫定）

- `HttpOnly`, `Secure`, `SameSite` 属性を付けたCookieでセッションを維持する案。
- D1にはセッショントークンのハッシュと有効期限を保存する案。
- ログアウトでサーバー側セッションを無効化。
- CSRF対策とCookie設定を実装する。
- セッション有効期間・更新方式・多端末ログアウトは未決定。

## 5. 認可

- 未ログイン: 公開済みコンテンツの読み取りのみ。
- ログイン済み: 自分の下書きの読み取り、自分の投稿・計画の作成。
- 所有者: 対象の編集・削除・公開。
- 管理者: 通報確認・違反投稿の削除（管理者識別方式は未決定）。

認可はUIのボタン非表示だけでなく、必ずサーバー側で実施する。

## 6. 退会

退会時に本人確認済みセッションを要求し、関連データとR2画像を削除する。削除済みユーザー名を残して投稿を維持する方式は採用しない。外部参照のピン枠は欠損表示にする。

## 7. 未決定

セッション期限、初回登録画面、handleの文字種・長さ、表示名の文字数、管理者認証、Googleアカウント連携解除時の扱い、再ログイン時の同一性。
