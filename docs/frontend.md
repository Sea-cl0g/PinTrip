# フロントエンド仕様

[目次へ](../README.md) · [API](./api.md) · [要件](./requirements.md)

## 1. 共通レイアウト（確定）

PCを優先して開発。左端にメニューバー、右側にメイン画面を置く。メニューは「マップ」「投稿一覧（名称未定）」「旅行計画」を基本とする。

### マップ
- 地図をメイン表示。右上に本文・ハッシュタグ検索窓。
- 検索窓付近に絞り込みボタンを配置する構想。ただし、いいね済み等の絞り込みは実装優先度未決定。
- ピン中央に絵文字を表示。ピンの詳細なデザインは別途決定。
- ピン選択で投稿内容を画面右側に表示。独立した投稿詳細ページは設けない。
- 投稿の座標を用いて「地図アプリで開く」ボタンを提供。
- 初期表示は現在地周辺。位置取得不可なら東京。ズーム倍率は未決定。
- 新規ピン設置はPCで右クリック、スマートフォンで長押し（スマホは後段実装）。

### 投稿一覧
- Xのタイムラインのように本文を縦方向に並べる。
- 新着順といいね数順の切替。
- 投稿カードのクリック・編集・いいね操作の細部は未決定。

### 旅行計画
- メイン領域左側に計画一覧、右側に選択した計画の内容。
- 未選択時は「旅行計画を追加」ボタン。
- 計画内容は絵文字・画像・本文・縦方向のピン列。
- 計画表示中は関連ピンを地図上でハイライト。ピン選択時は地図中心を移動。
- 計画編集画面の「追加」から地図へ移動し、選択したピンを計画へ追加。
- ドラッグ操作でピンの並び順を変更。
- 参照先が消えたピンは「ピンが見つかりません」とゴミ箱アイコンを表示。

## 2. 投稿編集UI

- タイトルと地図上の座標は必須。
- 本文はプレーンテキスト入力。
- 絵文字の処理にはemoji-regex、絵文字選択にはemoji-picker-reactを使用する。
- 画像の選択・追加・削除・順序変更。最大3枚、各5MB。
- 「下書き保存」「公開」を区別する。
- 公開済みピンの下書き戻しボタンは表示しない。
- 編集時の座標変更は許可される方向だが、公開後の参照計画への反映は未決定。

## 3. 計画編集UI

- タイトル、本文、絵文字、画像、ピンの順序、滞在時間、移動時間を編集。
- 下書きピンが含まれている場合は公開ボタンを無効化し、理由を表示する（**暫定UI案**）。
- 公開済み計画に下書きピンを追加した場合はAPIが拒否する。UIでも選択不可にする（**暫定UI案**）。
- 計画を削除してもピンは残す。

## 4. UI・デザインの共通ルール

### 基本原則（確定）

- shadcn/uiの基本UIを原則そのまま使い、Tailwind CSSで配置・レイアウトを構築する。Tailwindは必要に応じてテキスト・装飾・状態スタイルにも使用できる。
- `Button`、`Input`、`Textarea`、`Select`、`Checkbox`、`Dialog`、`Popover`、`Tabs`、`Card`、`DropdownMenu`等はshadcn/uiを優先し、単純に包み直すだけの独自部品を量産しない。Sidebarはshadcn/uiをベースに調整する。
- `PinCard`、`PinForm`、`PinDetail`、`MapView`、`PlanCard`、`PlanEditor`等のアプリ固有のまとまりは機能別に分離する。地図上の絵文字ピンのような独自性が必要な部分は独自実装とTailwindを使用できる。
- サイト独自の見た目は主に共通テーマで調整する。shadcn/uiの内部CSSを最初から全面的に書き換えず、標準の角丸・影・フォーカス等をできるだけ維持する。特別な理由のない個別指定や色・角丸・影・サイズの各所へのハードコードを避ける。
- レイアウト、Flexbox・Grid、余白、幅・高さ、スクロール、レスポンシブ、地図上のパネル配置にはTailwindを使う。例えば `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3` のようにブレークポイントを指定できる。具体的なスマートフォン画面構成は未決定で、PC優先を維持する。
- **方針**: 白・淡色中心の明るさ、清潔感、柔らかい親しみやすさと、地図操作の実用性を重視する。参考画像は方向性の参考であり、寸法や表現の確定仕様ではない。

#### ボタン（確定）

| 用途 | shadcn/uiの利用 |

### フォントとCSS管理

- **確定**: 基本UIはLINE Seed JPをグローバルに設定し、各コンポーネントに毎回 `font-sans` を付けない。サイドバー、検索、フォーム、ボタン、タブ、投稿タイトル（Bold）、日時、ユーザー名、ハッシュタグ、滞在・移動時間に使用する。
- **確定**: 投稿一覧を含む投稿本文、旅行日記、旅行計画の説明文にはZen Maru Gothicを使う。特殊な本文に `font-diary` を指定し、共通コンポーネント化で指定漏れを防ぐ。地図・操作UIでは実用性を重視し、旅行記本文で柔らかさを表現する。
- **確定**: フォントはCSS変数・Tailwindで統一管理する。Google Fontsの読み込みでは配信方式・文字種・速度を考慮し、正式な配信方法とライセンス条件を公開前に確認する。
- **確定**: 共通テーマ・フォント・基本スタイルはozakoが管理し、全員が無制限にグローバルCSSを変更しない。`<style>` タグに統一するという意味ではない。
- **提案**: 複雑な独自デザインが必要な場合のみ機能フォルダ内の `*.module.css` を使う。CSS Modulesの全面採用は未決定。ロゴ専用フォント、厳密な文字サイズ・ウェイト、ダークモードも未決定。

## 5. フロントエンド構成

```text
src/
  main.tsx          # Reactのエントリーポイント
  App.tsx           # ルーティング・アプリ全体の設定
  pages/            # ページ単位のコンポーネント
  components/       # ページ内で使用するUI・共通部品
  index.css         # 共通CSS・Tailwind CSS

public/
  data/             # JSON
```

- React + TypeScript。ルーティングにはReact Routerを使用する。具体的なURL・画面遷移・戻る操作は未決定。
- 共通UI・テーマはozako、投稿UIはyua、地図はozako、計画はha、認証連携とAPI契約はboo_manKnowが主に担当する。通報の担当は要確認。
- **提案**: ピンのフロント側取得・保持をyuaに集約し、`MapView` はProps等でピンを受け取って描画し、選択を親に通知する。画面固有の取得責務と見た目は必要に応じて分離する。
- 同じ意味の `Pin` 型を機能ごとに重複定義しない。型変更はboo_manKnowとyuaが確認し、ozako・haに知らせる。共有状態の保管場所は未決定。
- **確定**: 画像アップロードにはUppy、並び替えにはdnd-kit、アイコンにはLucide React、入力フォームにはReact Hook Form + Zod + shadcn/ui、日付にはdate-fnsを使用する。採用技術の一覧は [技術](./technology.md) を参照。

### モックと画面間連携

- **方針**: バックエンド未完成時も実APIと同じ形のモックを共通取得関数経由で使い、画面側の変更を最小限にして実APIへ切り替える。
- **提案**: 架空の公開サンプルを `public/data/pins.json`・`plans.json` 等に置き、`getPins()`・`getPlans()` 等から読み込む。Viteの場合は `/data/pins.json` 等で取得できる。共通APIクライアントで明示的な開発モードに応じて取得先を切り替え、画面ごとの直接JSON読み込みや重複した `fetch` を避ける。本番API障害時にモックへ自動フォールバックしない。
- 静的JSONはGETの試作向けで、作成・編集・削除やログインは再現できない。必要に応じた状態付きTypeScriptモックやMSWは提案であり、方式は未決定。公開される `public/` には秘密情報・実個人データ・認証情報を置かない。
- **提案**: 以下の情報をProps・コールバック等で明示的に受け渡す。データの所有者・共有状態の配置は関係者間で事前に合意する。

| 操作 | 受け渡す情報の案 | 関係者 |
|---|---|---|
| 地図右クリックから投稿作成 | 緯度・経度 | ozako → yua |
| 投稿選択から地図中心移動・詳細表示 | ピンID | yua ↔ ozako |
| 地図上のピン選択から投稿詳細 | ピンID | ozako → yua |
| 地図から計画へのピン追加 | 計画ID、ピンID | ozako ↔ ha |
| 計画内のピン選択から地図移動 | ピンID | ha → ozako |
| 計画内の並び替え | `plan_pins`のエントリID、並び順 | ha ↔ boo_manKnow |

## 6. 例外・空状態

- 現在地の取得拒否: 東京へフォールバック。
- 投稿0件: 空状態を表示。
- 下書きへの無権限アクセス: 内容を表示しない。
- APIエラー: 編集内容を失わないようにし、再試行可能なエラー表示（暫定）。
- 削除済みピン: 地図へ移動できないプレースホルダー表示。
