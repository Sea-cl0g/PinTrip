# セキュリティ・性能・運用仕様

[目次へ](../README.md) · [認証](./authentication.md) · [メディア](./media.md)

## 1. 想定負荷

- **確定**: 同時100人以上の利用は想定しない。
- **想定シナリオ**: 授業発表で80人程度が同時に読み取り、一部が書き込みを行う可能性。
- **確定方針**: 公開投稿の読み取りは約1分キャッシュ。
- **未決定**: API応答時間目標、具体的な負荷試験方法・成功基準。

D1はSQLite互換だが、ローカルの単一SQLiteファイルを直接共有する構成とは異なる。検索インデックスと読み取りキャッシュを設計し、実測で判断する。

## 2. 必須セキュリティ原則（暫定実装方針）

- Google IDトークンをサーバーで検証する。
- セッションCookieを安全に管理する。
- 下書きは所有者以外に返さない。
- すべての変更APIで所有者認可を行う。
- 入力値を検証し、SQLはパラメータ化する。
- 本文はプレーンテキストとして扱い、HTMLとして実行しない。
- 画像の実体を検証し、メタデータを除去する。
- シークレットはCloudflareの環境変数・シークレット管理機能に置き、Gitにコミットしない。
- 認証付きレスポンスを共有キャッシュに載せない。
- 投稿・画像・通報APIにレート制限を設ける。
- ブラウザ用Google Maps APIキーは公開され得る前提でリファラー/API制限を設定し、秘密値と混同しない。
- 公開される `public/` のモックデータには秘密情報・実個人データ・認証情報を含めない。

**方針**: Google Cloud・Cloudflareの設定、環境変数・シークレットと開発/本番の設定はboo_manKnowが管理する。具体的な環境分離は未決定。

## 3. スパム・通報

- API呼び出し制限を設ける（閾値未決定）。
- 通報はD1に記録する。
- 運営者が記録を見て手動削除する。
- 自動モデレーションや管理画面は初期必須ではない。

## 4. バックアップ・障害対応

- D1のバックアップ・復元方法は未決定。
- R2画像のバックアップ方針は未決定。
- エラー監視は原則Cloudflareダッシュボードの標準機能を使用し、独自監視基盤は作らない。
- R2とD1を跨ぐ削除・登録では失敗時の整合性を確認する。

## 5. ブラウザ・端末

一般的なブラウザを対象とし、PC版を先行実装。スマートフォン対応は後段。対応ブラウザ・バージョンは未決定。

## 6. 運用終了

最終発表後の公開継続、公開終了時のユーザーデータ・画像削除時期は未決定。
